# Tasks

All `idf.py` commands run with the project directory as argument (`idf.py -C esp32-ssd1315-dashboard ...`) or from a shell the operator has already placed there; the IDF environment (`export.sh` of `~/.espressif/v6.1/esp-idf`) must be active. Flashing and anything that needs the board is done by the operator.

## 3. Wi-Fi

- [ ] 3.1 Add `net.hpp/.cpp`: NVS, netif, event loop, station bring-up and the event handler from design.md "Wi-Fi", posting `WIFI_UP` / `WIFI_DOWN` (with the attempt count) to the main queue; add the static queue and the event enum to `app_main` with the CONNECTING / ONLINE / OFFLINE transitions and screens (`SSID` + `try N`, `fetching` placeholder, `no wifi`). ## 4. Fetch and status

- [ ] 4.1 Add `status.cpp` (cJSON + ETL only, no IDF headers): `format_elapsed` and `screen_from_daily(etl::string_view body)` returning `etl::expected<Screen, FetchError>`, per design.md "JSON to screen". Add `status.cpp` and cJSON to the host tests' `CMakeLists.txt`, `format_elapsed` and `screen_from_daily` to the shim, and verify with `host_tests/test_status.py`: 0, 5, 59, 60, 65, 179, 180, 347, 1439 minutes → `0m`, `5m`, `59m`, `1h00`, `1h05`, `2h59`, `3h`, `5h`, `23h`; `timeSince [2,15]` + debt 2.6 → `2h15` / 2; debt 0.3 → 0; debt -0.8 → 0; `timeSince null` + `fromWakeupMins 100` → `1h40`; `stats null` → `no wakeup`; a body with 100 generated `sittings` entries → the same status; not JSON, missing `stats`, `sittingDebt: "x"`, `timeSince: [1]` → `bad response`.
- [ ] 4.2 Add `fetch.hpp/.cpp`: the static URL and body buffer, `esp_http_client` initialised once with the Bearer header, bundle attach and 10 s timeout, the `ON_DATA` accumulator with the overflow flag, the error mapping table, and the fetch task that waits on a notification, performs, parses with `status.cpp`, posts `FETCH_DONE` and logs the outcome with `esp_get_minimum_free_heap_size()`. Wire the periodic `esp_timer` (`CONFIG_DASH_REFRESH_SECONDS`) and the ONLINE transitions in `app_main`: TICK and WIFI_UP notify the fetch task; FETCH_DONE redraws; the previous screen stays until then. Verify against a scratchpad stub server on the Mac (`http` scheme, Mac IP, stub port, set in `menuconfig`) that answers a canned daily body, 401, 502, non-JSON, a 20 KB body, and a handler that accepts and never answers: the panel shows `since` / `2h15` / `missing 2`, `bad token`, `server 502`, `bad response`, `bad response`, `no network` (the last within 15 s), the stub sees `Authorization: Bearer <token>` and no `/login` request, requests arrive about every 30 s, the numbers change in place without an intermediate screen, and no monitor line contains the token.
- [ ] 4.3 Switch `menuconfig` back to `https` / `sitting.lviv.social` / `443` with the operator's real token and verify on the board that the panel shows the same numbers as the web app, that the monitor's minimum-free-heap line stays flat over 10 minutes of refreshes, and that `idf.py size` reports the app under the 1.5 MB partition with margin; record the app size in design.md "Risks".
